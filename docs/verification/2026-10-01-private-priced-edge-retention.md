# Retain prospective NFL priced-edge evidence privately

The existing daily worker evaluates original NFL forecasts and recommendations against matching recorded sportsbook prices. Until this change it computed the frozen prospective assessment, printed generic success, and deleted both temporary JSON files. No report was retained, so a later review could not compare successive cohort counts or recover the exact audit output from that daily run.

`nfl-priced-prospective-checkpoint-v1` stores the **unchanged** assessment and the prospective aggregate sections of both audits in the existing restricted, append-only `analytics.prospective_audit_reports` table. The recording includes the observation timestamp and evaluator source hashes. The database checks a JSON protocol/version match, timestamp match, payload digest, and maximum size. Only `sportsbet_worker` may select or insert; browser roles remain denied and the worker cannot update or delete. The daily job still logs only generic success or a sanitized exception type, removes its temporary files, and does not upload the private report as an artifact. A failed storage step fails that audit step; it cannot rewrite a forecast or create a pick.

The report retains both the all-forecast and recommendation denominators, decided and paired-game counts, matching-market Brier comparison and its game-cluster interval, authenticated hypothetical returns, and the unchanged evidence-gate status. The frozen 50 paired games, 100 decided recommendations, 30 recommendation games, negative model-minus-market upper bound, and positive return lower bound remain. The report always sets `promote=false` and `target_verified=false`; storage or a favorable status never changes production picks.

This adds no provider request, odds credit use, payment, bet, model fit, threshold change, public output, or broader database role permission. The migration expands only the exact protocol allowlist of the existing private table. Downgrade refuses to erase retained priced reports.

Verification: focused unit tests cover protocol identity, assessor output, hash binding, nonpromotion, nonfinite values, and timezone requirements; the migration test inserts both exact protocols as the restricted worker and checks role boundaries; the workflow test checks that private results never enter step summaries or artifacts. The next protected daily run, after migration 0040 is deployed, must create one `nfl-priced-prospective-checkpoint-v1` row with a valid hash and no raw report in its Actions log. Until that production row is observed, this is a reviewed implementation, not deployed evidence of an edge.

Consumer scope: the Results ledger includes all recorded model versions, while the Evaluation panel shows its selected model version. Both panels now label that difference and each past pick shows its model version. This clarifies the live 2026-10-02 checkpoint: seven settled original NFL-model picks (3 wins, 4 losses), versus one pending current NFL-history-model recommendation. No outcome or win rate is recomputed by this copy change.
The production NFL model is now empirical-jeffreys-v4-nfl-history-v1; the older v4 audit above cannot accrue its future games. The same existing daily job therefore also runs the already frozen nfl-history-priced-prospective-v1 evaluator (start 2026-09-29 05:45 UTC) and stores its aggregate under that distinct protocol in the same restricted table. It checks the protocol and evaluator digests against the committed frozen source versions, two cohort identities, observation time and promote=false, and adds target_verified=false to the private storage envelope. A changed evaluator fails retention and needs a new protocol. The current-model audit has its own 50 paired games, 100 decided recommendations and 30 recommendation games gate. Old-model records never enter it. The evaluator is reused unchanged; the new step reads already captured prices and authenticated outcomes only.

After deployment, verify that the protected daily run stores one report for each protocol, with the current-model row's counts agreeing with a read-only nfl_history_edge replay and no private report in logs or public artifacts. Until then, neither report demonstrates an edge or production retention.
