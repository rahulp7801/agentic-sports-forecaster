# CFB explicit receiving-history recovery — 2026-10-02

A current CFB quote-coverage audit found three athletes whose receiving-yard and reception histories were below the existing 20-game minimum despite recorded prior games with NULL receiving categories. NULL stayed unknown throughout the audit.

Six bounded, free player game-log responses explicitly reported zero receiving yards and zero receptions for 13 prior athlete/game identities. Thirteen separately archived final game summaries showed completed regular-season events and positive rushing offensive activity for those exact athletes. Each player log was observed after its final summary. The existing `cfb_final_evidence.inspect_bundle` contract validates event, team, athlete, season, week, scores, stat columns, source hashes and chronology; all 13 passed. The source bundle and individual identities remain in ignored local research storage.

The provider's game-log schema includes unrelated `type=event` categories without an `events` member. The final-evidence parser previously raised `KeyError` while traversing them. It now treats only that missing auxiliary list as empty. A missing target game still yields `explicit_game_stats_missing`; conflicting, nonfinal and unauthenticated evidence still fails. The production model and qualification thresholds are untouched.

The hosted read-only completeness audit classified 13 verified primary-history gaps. Across the three athletes, both receiving fields would change from 10, 19 and 18 known prior games to 20. The reviewed append-only plan proposed exactly 13 inserts and zero already retained.

After exact-head CI passed, the existing guarded supplement command applied that reviewed 13-row plan to production as a separate data operation. A subsequent read-only preview proposed zero further inserts and counted 13 retained; the effective view showed 20 usable receiving-yard and reception rows for each athlete. Replaying the production query at five original forecast cutoffs still returned the unchanged recorded samples (10, 18 or 19), while a current-time read returned 20. The source and insert timestamps therefore preserve the earlier forecast boundary. Database size after the apply was 283,315,347 bytes, under the documented free-tier database quota.

This is a prospective input repair, not a historical as-of backtest. The newly observed receipts cannot be retroactively used by previously recorded forecasts. It does not establish an edge or guarantee a qualified pick. Seventy-four focused final-evidence, completeness and supplement tests pass. The individual source bundle and reviewed apply digest remain in private storage. The code change adds no automatic database write, paid request, wager or model promotion; the guarded 13-row data apply above was the only production write in this phase.
